# M-Pilot 포트폴리오: 정혜윤

> 물류 설비 장애 신고를 **셀프 가이드** 또는 **엔지니어 RAG 대화**로 처리하는 팀 프로젝트(7명)에서
> **답변 생성(Generator) · 프롬프트 설계 · UX/UI 개선**을 맡았습니다.
> 모든 데이터(매뉴얼, 에러코드, 서비스 이력)는 가상입니다.

**기술 스택**: Python 3.12, LangChain, Pydantic, OpenAI API, Gradio(CSS), pytest

## 프로젝트 한 줄 소개

고객이 설비와 에러코드를 골라 신고하면, 고객이 조치할 수 있는 고장은 매뉴얼 근거의 셀프 가이드로, 그 밖은 엔지니어에게 접수해 **매뉴얼과 확정된 과거 조치**에 근거한 답을 출처와 함께 보여 줍니다. 근거가 없으면 지어내지 않고 그 사실만 알립니다.

## 내가 한 일

### 1. 답변 생성 (`mpilot/rag/generator.py`)

"그럴듯한 문장"이 아니라 "믿고 따라 할 수 있는 조치"만 나가게 하는 것이 목표였습니다.

- **구조화 출력**: LangChain `with_structured_output(Answer)`로 답변을 단계별 구조로 받음
- **인용 검증**: 모든 단계의 출처가 실제 검색 근거 `(종류, 근거 ID)`와 위치에 맞고 설비가 일치할 때만 답변을 보여 줌. 어긋나면 답변을 내보내지 않음
- **질문 라우팅**: 질문이 묻는 설비를 판단해 해당 설비 자료에서 검색
- **대화 맥락**: 최근 6턴만 반영하고, 메모 길이를 제한해 입력이 과하게 길어지는 것을 막음
- **안전 처리**: 근거 텍스트 속 태그를 이스케이프해 프롬프트가 흐트러지지 않게 하고, 모델·검색 장애는 `DependencyError`로 모아 고정 문구로 안내
- **테스트**: `tests/test_generator.py` 23개

### 2. 프롬프트 설계 (`prompts/`)

- 근거 밖의 내용은 답하지 않도록 규칙화
- **고객 안내는 매뉴얼 근거만** 사용 (과거 이력은 엔지니어 답변에만 사용)
- 근거가 부족하면 조치 단계 없이 "근거 부족"만 알리고 보류하도록 설계

### 3. UX/UI 개선 (`mpilot/ui/`)

- **[원문보기] 모달**: 답변의 출처를 한 번의 클릭으로 원문에서 바로 확인 (CSS로 구현)
- **역할별 화면**: 고객·엔지니어 앱을 색상·내비게이션으로 구분
- **채팅 화면 다듬기**: 스크롤되는 채팅 박스, 고정 툴바, 둥근 입력창, 상태 라벨, 오류 고정 문구
